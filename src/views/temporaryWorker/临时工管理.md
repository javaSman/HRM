## 模块概述

临时工管理模块覆盖临时工从**需求申请 → 审批 → 面试 → 入档 → 档案管理**的完整链路，包含五类页面：

| 模块 | 目录 | 数据主表 | 职责 |
|------|------|----------|------|
| 申请 | `apply/` | 临时工需求申请 | 申请人发起、查询、撤回临时工需求 |
| 审批 | `approval/` | 同申请模块 | 审批人对待办需求同意 / 驳回（复用申请列表） |
| 面试 | `interview/` | 访客中心申请 `hrm_fkzx_sq` | 对劳动派遣人员批量登记面试结果 |
| 入档 | `archive/` | 访客中心申请 `hrm_fkzx_sq` | 面试通过者按工种名额添加为临时工，或删除 |
| 档案 | `file/` | 临时工档案 `tempWorkerArchive` | 档案录入/编辑、在职离职、入住申请、导入导出、打卡导出 |

### 技术栈

- Vue 2.6.10（Options API）+ ant-design-vue 1.7.2
- JEECG Boot 列表模式：`JeecgListMixin` + `getAction/postAction/putAction/deleteAction`
- Less，模块统一主题文件 `temporary-worker-theme.less`
- 各页面由 JEECG 后台菜单动态路由加载，前端无静态路由配置

## 整体业务流程

```
┌─────────────────────────────────────────────────────────────────┐
│  需求侧（tempWorkerApply）                                        │
│                                                                 │
│  申请人发起需求 ──► 审批人审批 ──► 已通过（status=1）             │
│      │                │                                         │
│      │                ├── 同意（approvalResult=1）               │
│      │                └── 驳回（approvalResult=2 → 不通过）       │
│      └── 审批中可撤回（status=2 已撤回）                           │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  用工侧（访客中心 hrm_fkzx_sq，来访类型 lflx=4 劳动派遣）          │
│                                                                 │
│  劳动派遣登记审批通过（zt=1）                                     │
│        │                                                        │
│        ▼                                                        │
│   面试登记（interview）                                          │
│        ├── mszt=0 未面试（默认）                                  │
│        ├── mszt=1 已通过 ──► 入档页可见（archive，mszt 固定=1）    │
│        └── mszt=2 不通过                                         │
│                         │                                        │
│                         ▼                                        │
│              选择工种 + 部门分配（名额规则）                        │
│                         │                                        │
│                         ▼                                        │
│            addByLdpq 转为临时工（isLsgda=1）
│                         │
│                         ▼
│        ┌──────────────────────────────────────┐
│        │ 档案管理（file，tempWorkerArchive）    │
│        │                                       │
│        │  入档数据 / 手工录入 add ──► 在职档案   │
│        │    │                                   │
│        │    ├── 内宿=是 ──► 提交入住申请审批      │
│        │    ├── 编辑 edit                        │
│        │    └── 办理离职 leave ──► 离职          │
│        │                                       │
│        │  Excel 导入导出 / 打卡记录导出           │
│        └──────────────────────────────────────┘
│                                                                 │
│  未入档记录也可 deleteBatch 删除源登记                             │
└─────────────────────────────────────────────────────────────────┘
```

> **注意**：
> - 面试与入档两个页面操作的是同一张表 `hrm_fkzx_sq`，列表接口同为 `/fkzx/hrmFkzxSq/list`，仅固定过滤条件不同（入档页额外固定 `mszt=1`）。
> - 入档页的 `addByLdpq` 与档案页（file）的手工录入写入的是**同一张档案表** `tempWorkerArchive`，因此入档提交后人员直接出现在档案页「在职」列表。

## 功能模块

### 1. 申请与审批模块（`apply/`、`approval/`）

`apply/index.vue` 是申请端与审批端**共用的列表页**，通过 prop 切换：

| props.mode | 列表接口 | 显示的操作 |
|------------|----------|-----------|
| `apply`（默认） | `/lsggl/tempWorkerApply/list` | 新增、详情、撤回 |
| `audit` | `/lsggl/tempWorkerAudit/list` | 详情、审批 |

`approval/index.vue` 仅 30 余行，内部渲染 `<applyList mode="audit">`。

**申请状态（字段 `status`，字典 `temp_worker_apply_status`）**：

| 值 | 状态 | Tab | 样式类 |
|----|------|-----|--------|
| `0` | 审批中 | 审批中 | pending（橙，圆点闪烁） |
| `1` | 已通过 | 已通过 | handled（绿） |
| `3` | 不通过 | 不通过 | rejected（红） |
| `2` | 已撤回 | 已撤回 | cancelled（灰） |
| — | — | 全部 | — |

**主要功能点**：

- ✅ 需求部门级联筛选（组织树 `/org/hrmOrg/loadTreeRoot`）、申请人姓名模糊查询
- ✅ 全部 / 审批中 / 已通过 / 不通过 / 已撤回五个胶囊 Tab，数量由统计接口按中文文案匹配汇总
- ✅ 新增需求：多申请人、多需求明细（新增 / 续签）、按部门动态加载审批流程节点
- ✅ 审批中（status=0）的申请，申请人确认后可撤回
- ✅ 审批模式下查看待办、填写审批意见、同意 / 驳回
- ✅ 详情内审批时间轴展示申请人、各级审批与抄送状态

### 2. 面试模块（`interview/`）

对劳动派遣登记审批已通过（`lflx=4、zt=1`）的人员登记面试结果。

**面试状态（字段 `mszt`）**：`0` 未面试（蓝）/ `1` 已通过（绿）/ `2` 不通过（红）。

**主要功能点**：

- ✅ 四张统计卡片：劳动派遣总数 / 未面试 / 已通过 / 不通过
- ✅ 按访客姓名、接待人、派遣公司（字典 `hrm_fkzx_sq_pqgs`）、预计来访时间筛选
- ✅ 未面试 / 已通过 / 不通过状态 Tab
- ✅ 勾选后批量登记；对已有结果的记录重新登记时给出覆盖提醒
- ✅ 详情复用访客中心 `EmployeeVisitorDetail`（`detailType=temp`）
- ✅ 面试【已通过】数据自动进入入档页

> 详细说明见 [interview/README.md](interview/README.md)。

### 3. 入档模块（`archive/`）

展示**审批通过且面试通过**（`lflx=4、zt=1、mszt=1`）的劳动派遣人员，按入档标记分 Tab：

**入档状态（字段 `isLsgda`）**：`0` 未入档 / `1` 已入档。

**主要功能点**：

- ✅ 三张统计卡片：入档总数 / 未入档 / 已入档
- ✅ 未入档 / 已入档 Tab；已入档行 checkbox 置灰不可勾选
- ✅ 勾选后「添加进入临时工」：选择工种，按该工种剩余名额生成部门分配预览
  - 名额内：默认分配第一个可分配部门，可逐人手动改选
  - 超出名额：标记「暂不分配岗位」，仍可提交
  - 提示分三档：常规 / 名额将满 / 超出名额（提单人数已满）
- ✅ 未入档记录可批量删除（二次确认，删除源劳动派遣登记）
- ✅ 详情复用访客中心 `EmployeeVisitorDetail`（`detailType=temp`）

### 4. 档案模块（`file/`）

临时工档案（`tempWorkerArchive`）的列表与维护页，数据来源有两条路径：入档页 `addByLdpq` 自动转入、本页手工录入。

**档案状态（字段 `status`）**：`0` 在职 / `1` 离职。

**主要功能点**：

- ✅ 在职 / 离职胶囊 Tab，顶部两张统计卡片（统计编码 `hrm_temp_worker_archive`）
- ✅ 按姓名、工号（模糊）、入职公司/部门（级联）、入职日期、离职日期筛选
- ✅ 录入 / 编辑档案：基本信息、公司-部门-岗位联动、自动生成工号、银行、合同、照片
- ✅ 内宿集成：「是否内宿=是」时展开入住申请表单（区域/类型/日期/原因 + 动态审批节点），保存档案同时提交入住申请；已有入住申请记录时相关字段只读
- ✅ 在职记录可办理离职（默认当天）
- ✅ Excel 导入（模板下载、单 .xls 上传、成功/失败明细与错误文件提示）
- ✅ 档案列表导出、打卡记录按年月导出（自动附带 `employeeType=临时工` 与当前查询条件）
- ✅ 用户级字段列配置（右侧边栏勾选列，配置持久化到后端，编码 `TempWorkerArchive`）

### 📄 `apply/modules/TemporaryWorkerModal.vue` — `TemporaryWorkerModal`

新增临时工需求弹窗（`edit` 当前仅由 `add()` 以空对象调用），提交成功后 `emit('ok')`。

- **对外方法**：`add()`；`edit(record)`（合并默认 model，带入当前登录人部门与工号）
- **基础信息**：部门（`deptId/deptName`，级联选择）、申请人（`j-select-employee` 多选，`applicantList: [{userId,userName,userCode}]`）
- **需求明细 `demandRows`**（可增删 / 复制多行）：

| 字段 | 含义 |
|------|------|
| `workType` / `workTypeName` | 工种（按部门子序列加载） |
| `demandNature` | 需求性质：新增 / 续签 |
| `personCount` | 人数（新增手填；续签自动等于续签人数） |
| `xqNos` | 续签人员工号（续签时从部门在职临时工多选） |
| `workDays`、`startDate`、`endDate` | 工期与起止日期 |
| `serviceProject`、`attachment` | 服务项目、附件 |

- **审批流程**：按 `sqmkCode='临时工申请'` + 部门拉取动态节点，支持会签 / 或签、抄送节点、直属主管 / 经理 / 总监空级审批、节点自选审批人（不覆盖默认人）
- **提交体 formData**：`deptId/deptName/applicantId/applicantName/applicantCode/createByNo/itemList/customProcessConfigurationDTOList`
- **核心方法**：`loadProcessNodes()`、`buildProcessDTOList()`、`handleXqrChange()`、`addDemandRow()/removeDemandRow()/duplicateDemand()`、`handleDemandNatureChange()`、`loadRenewWorkers(deptId)`、`handleSelectValue()`、`loadWorkTypeOptions(deptId)`、`handleOk()`

### 📄 `archive/modules/AddWorkerModal.vue` — `AddWorkerModal`

按工种名额批量添加为临时工，成功后 `emit('ok')`。

- **核心数据**：
  - `workTypeOptions`：工种列表，每项含 `workTypeName`、`remainingCount` 剩余名额、`deptList`（可分配部门，含 `itemId/deptPath/remainingCount`）

## 开发规范

### 注释

- Vue 文件顶部保留文件头注释：

```vue
<!--
  @description 文件描述
  @date 日期
  @functionality 主要功能说明
-->
```

- 方法使用 JSDoc（`@param` / `@returns`），data 字段使用 `/** 说明 */` 行内注释

### 命名

- 组件文件 PascalCase；页面入口统一 `index.vue`
- 事件处理 `handleXxx`、数据加载 `loadXxx`、布尔判断 `isXxx/hasXxx`
- 查询参数对象统一命名 `queryParam`

### 样式

- 统一 `<style lang="less" scoped>`，颜色 / 边框 / 阴影优先使用主题变量，不直接硬编码
- 修改 ant-design-vue 内部样式使用 `/deep/`
- 面试页采用页面根容器整页滚动（`overflow-y:auto`），表格区取消内部滚动；新增弹窗等沿用主题既有卡片模式

### 接口调用

- 统一使用 `@/api/manage` 的方法，不直接使用 axios
- 以 `res.success` 判断成功，失败信息通过 `$message.warning / error` 反馈用户
- 模糊查询按 JEECG 规则包装 `*关键词*`

### Git

- 仅提交本任务直接产出的文件，使用 `git add <具体文件>`，不使用 `git add .`
- 不覆盖、不回退他人未提交的改动；遇冲突先报告
- Commit 示例：`【feat：临时工面试结果批量登记】`
