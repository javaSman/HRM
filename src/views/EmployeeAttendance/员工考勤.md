## 核心业务关系

```
考勤机打卡日志（hrm_attlog）
    │
    │ 系统定时/手动运算
    ↓
正常考勤表（hr_kq_yg）────────────────────── 日常查看、统计
    │
    │ 规则判定（迟到/早退/缺卡/旷工）
    ↓
异常考勤表（hr_yckq_yg）──────────────────── HR 处理、审核
```

正常考勤和异常考勤是**两张独立的数据库表**、**两套独立的列表页**，但共享相同的 UI 架构（状态标签页 + 筛选 + 表格 + 字段配置 + 事业部快捷入口）。

## 状态标签页设计（卡片式）

列表页顶部使用 `a-tabs type="card"` 实现卡片式标签页，替代了旧版的普通标签样式。每个标签显示状态名称和数量：

### 正常考勤标签

| 标签 | value | 配色 |
|------|-------|------|
| 全部 | `""` | 默认蓝 |
| 正常 | `NORMAL` | 绿色 |
| 早退 | `LEAVE_EARLY` | 紫色 |
| 迟到 | `BE_LATE` | 橙色 |
| 缺卡 | `MISSING` | 蓝色 |
| 旷工 | `ABSENT` | 红色 |
| 其他 | `OTHER` | 灰色 |

### 异常考勤标签

| 标签 | value | 配色 |
|------|-------|------|
| 全部 | `""` | 默认蓝 |
| 早退 | `LEAVE_EARLY` | 紫色 |
| 迟到 | `BE_LATE` | 橙色 |
| 缺卡 | `MISSING` | 蓝色 |
| 旷工 | `ABSENT` | 红色 |
| 其他 | `OTHER` | 灰色 |

> 异常考勤无"正常"标签，因为异常表中不存在正常记录。

标签页通过 `data-status` 属性结合 CSS `:has()` 选择器实现不同状态的配色——未激活状态下各状态显示对应颜色，激活状态下显示深色背景。

标签数量通过 `getDictOptions()` 方法调用 `/hr_kq_yg/hrKqYg/getTotal`（或异常考勤对应接口）获取，在 `watch activeKey` 和 Tab 切换时实时刷新。

## 字段配置功能（ColumnConfigSidebar）

新增的字段配置功能允许用户自定义表格列的显示和顺序：

```
右侧抽屉（380px 宽）
├── 头部：蓝色渐变标题栏 "字段配置"
├── 提示：可拖拽调整字段显示顺序，取消勾选将隐藏该列
├── 搜索框：快速定位字段
└── 字段列表（vuedraggable 拖拽排序）
    ├── ☰ 拖拽手柄
    ├── ☑ 复选框（勾选 = 显示）
    └── 字段中文名
```

**数据流**：
- 读取：`GET /hr_field_config/hrFieldConfig/list?code=HrKqYg`（正常）或 `code=HrYckqYg`（异常）
- 保存：`POST /hr_field_config/hrFieldConfig/editBatch`，批量提交更新后的列配置
- 保存后调用 `getColumnConfig()` 重新加载，`columnTakeEffect` 控制是否应用自定义列配置

**列配置逻辑**：当 `columnTakeEffect` 为 true 时，`columns` 计算属性会根据 `columnConfig` 中的 `fieldVisible` 和 `fieldSort` 过滤并排序列，最终按 `fieldSort` 升序排列。考勤规则和操作列始终固定在右侧（`fieldSort: 9999`）。

## 事业部快捷入口的设计

`list/` 和 `yc/list/` 下各有 10 个文件，每个文件是一个**极简的页面组件**：

```vue
<!-- 以 list/it_list.vue 为例 -->
<template>
  <Alist :url="url.list" :activeKey="activeKey" />
</template>
<script>
import Alist from '../indexList'
export default {
  data() {
    return {
      activeKey: '2059089110892486657',  // 硬编码的事业部 ID
    }
  }

</script>
```

**为什么这样设计？** 系统需要为每个事业部提供独立的菜单入口（左侧导航直接跳转到某事业部的考勤页）。每个文件就是一个路由目标——不需要参数传递，打开即显示对应事业部的数据。

## 关键业务流程

### 数据生成

考勤数据不是实时录入的，而是**系统运算生成**：

```
考勤机原始打卡日志（hrm_attlog）
    │
    │ 系统按考勤规则（打卡时段、迟到宽限、加班规则等）进行匹配运算
    │ 生成每人每天的工时统计、异常标记
    ↓
正常考勤表（hr_kq_yg）
    │
    │ 迟到/早退/缺卡/旷工 的记录被标记
    ↓
异常考勤表（hr_yckq_yg）→ 等待 HR 处理和审核
```

kfadmin 用户可在列表页通过“重新生成”按钮，指定日期范围提交 `attendance_recalc_task`。
按钮不再同步调用存储过程；任务由实时 Worker 完成打卡读取、插槽匹配、状态/工时计算、`hr_kq_yg` 写回和异常同步。
任务进度可在“考勤实时计算监控”页面查看。

### 状态标签页筛选

列表页顶部使用卡片式标签页进行状态筛选：

1. 点击标签 → `activeKey` 变化 → `watch` 触发 → 调用 `getDictOptions()` 更新各标签计数
2. 同时触发 `searchQuery(1)` 重新查询，`activeKey` 值作为 `superQueryParams` 中的 `attendanceStatus` 条件
3. 通过 `customSuperQueryParams`（JeecgListMixin 新增字段）将状态条件合并到查询参数中

### 打卡记录查看

列表每行有一个"打卡记录"链接 → 打开 `HrKqYgClockRecordModal` → 调用 `/hrm/hrmAttlog/list` 传入工号和日期 → 展示该员工当天的**原始打卡机日志**（每次刷卡的精确时间、打卡方式）。

弹窗支持多出勤状态拼接展示：当一条记录有多个状态（如"迟到+早退"），会以多个彩色标签分别展示。

这个弹窗的定位是**溯源**：当对考勤结果有疑问时，查看原始打卡记录来核实。

### 考勤规则详情

点击出勤状态标签或考勤规则标签 → 打开 `HrKqRuleDetailModal`（左侧抽屉 500px）→ 展示：
- **基本信息**：考勤组（部门/岗位/人员标签）、规则说明、打卡方式
- **时间段明细**：表格列出每个时段的签到/签退时间范围、是否弹性、迟到宽限等

该组件从 `j-modal` 重构为 `a-drawer`，placement="left"，带蓝色渐变头部样式。

### 异常处理（⚠ 接口待对接）

```
HR 在异常考勤列表看到一条异常
  → 点击"处理" → HrKqYcHandleModal
    → 查看异常说明
    → 修正打卡时间（10 个时间段可编辑）
    → 选择处理状态
    → 填写处理备注
    → 上传附件
    → 提交（TODO: 接口待对接）
  → HR 审核 → HrKqYcAuditModal
    → 界面与处理弹窗完全一致
    → 提交（TODO: 接口待对接）
```

> **注意**：`HrKqYcHandleModal` 和 `HrKqYcAuditModal` 当前代码几乎完全相同（模板、数据、方法、TODO 注释均一致），仅 title 不同。预计后续会根据接口区分处理逻辑（如审核不可修改打卡时间、增加审核意见字段等）。

## 筛选逻辑

| 筛选方式 | 组件 | queryParam 字段 |
|---|---|---|
| 状态标签页 | a-tabs (type="card") | `activeKey` → `superQueryParams.attendanceStatus` |
| 月份选择 | a-month-picker | `dateTime`（YYYY-MM） |
| 日期范围 | a-range-picker | `skrq_begin` + `skrq_end` |
| 公司选择 | a-select | `deptBelong` |
| 部门级联 | 组织级联选择器 | `dept`（取 path 最后一级） |

切换规则：
- 选择日期范围 → 自动清空月份选择
- 选择月份 → 自动清空日期范围
- 切换状态标签 → 通过 `customSuperQueryParams` 附加 `attendanceStatus` 查询条件，重置到第 1 页
- 公司选择器始终可见（不再根据 activeKey 隐藏）
