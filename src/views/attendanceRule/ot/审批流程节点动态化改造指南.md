# 审批流程节点动态化改造指南

> 适用场景：原模块的审批流程节点是写死的（如部门审批、HR审批、抄送），需要改为从后端接口动态拉取节点配置。

## 涉及接口

### 获取流程节点配置列表

| 项 | 值 |
|---|---|
| 接口路径 | `/process/customProcessConfiguration/getLcjdList` |
| 请求方法 | GET / `getAction` |
| 入参 | `sqmkCode`（申请模块编码，如 `'加班申请'`）、`dept`（部门ID） |
| 返回 | 节点数组（见下文数据结构） |

> ⚠️ 路径不需要加 `/qr-hrm` 前缀，axios baseURL 已包含。

---

### 4. methods：新增工具方法

```js
/** 判断节点是否为抄送节点（nodeProperties: 1=审批, 2=抄送） */
isCcNode(node) {
  return node && Number(node.nodeProperties) === 2
},

/** 判断节点是否为 kjSprType 类型节点（users 为 null 时展示 kjSprType_dictText） */
isKjSprTypeNode(node) {
  if (!node) return false
  return node.users === null && node.kjSprType_dictText
},

/** 判断节点是否显示添加审批人按钮（isselfSelect===1 或 sprScope===4 时显示） */
hasSprScope(node) {
  if (!node) return false
  return Number(node.isselfSelect) === 1 || Number(node.sprScope) === 4
},

/** 从节点配置中提取默认人员（users/roles/departments 合并去重） */
extractDefaultPersons(node) {
  const list = []
  const addItems = (arr, idKey, nameKey) => {
    if (!Array.isArray(arr)) return
    arr.forEach(item => {
      const ids = (item[idKey] || '').toString().split(',').filter(Boolean)
      const names = (item[nameKey] || '').toString().split(',').filter(Boolean)
      ids.forEach((id, idx) => {
        list.push({ id: id.trim(), name: (names[idx] || id).trim() })
      })
    })
  }
  addItems(node.users, 'chooseObjects', 'chooseObjectsName')
  addItems(node.roles, 'chooseObjects', 'chooseObjectsName')
  addItems(node.departments, 'chooseObjects', 'chooseObjectsName')
  const map = new Map()
  list.forEach(item => { if (!map.has(item.id)) map.set(item.id, item) })
  return Array.from(map.values())
},

/** 加载流程节点（在 edit/add 时调用） */
loadProcessNodes() {
  if (this.title === '详情') {
    this.processNodeList = []
    this.nodeObjList = []
    return
  }
  const dept = this.model.dept || (this.perInfo && this.perInfo.dept) || ''
  if (!dept) {
    this.processNodeList = []
    this.nodeObjList = []
    return
  }
  getAction(this.url.getLcjdList, {
    sqmkCode: '加班申请',   // 按实际模块填写，如 '加班申请'、'请假申请' 等
    dept: dept
  }).then(res => {
    if (res.success && Array.isArray(res.result)) {
      const list = res.result.slice().sort((a, b) => Number(a.px) - Number(b.px))
      this.processNodeList = list
      this.nodeObjList = list.map(node => {
        const defaultPersons = this.extractDefaultPersons(node)
        return {
          arr: defaultPersons,
          str: defaultPersons.map(p => p.name).join(',')
        }
      })
    } else {
      this.processNodeList = []
      this.nodeObjList = []
      this.$message.warning(res.message || '没有匹配到审批模板')
    }
  }).catch(() => {
    this.processNodeList = []
    this.nodeObjList = []
  })
},
```

> 💡 接口返回失败时给用户一个友好提示（如"没有匹配到审批模板"），避免节点区域空白用户不知道原因。
>
> 💡 显示条件从原来的 `(!model.spStatus || model.spStatus == 3 || model.spStatus == 4) && title != '详情'` 简化为 `title != '详情'`，去掉了 `spStatus` 状态判断。

### 5. methods：改造选择人员的方法（从字符串 key 改为数字索引）

> ⚠️ 注意：`handleSelectValue` 采用**追加合并**逻辑，避免新选择的人员覆盖接口返回的默认人员。

```js
handleSelectValue(index, value, rows) {
  if (this.nodeObjList[index]) {
    // 将新选择的人员追加到现有列表中，按 id 去重
    const existingArr = this.nodeObjList[index].arr || []
    const map = new Map()
    existingArr.forEach(item => map.set(item.id, item))
    rows.forEach(item => {
      if (!map.has(item.id)) {
        map.set(item.id, item)
      }
    })
    const mergedArr = Array.from(map.values())
    this.nodeObjList[index].arr = mergedArr
    this.nodeObjList[index].str = mergedArr.map(p => p.name).join(',')
  }
},
handleEmployeeTagClose(event, index, id) {
  if (event && event.preventDefault) event.preventDefault()
  if (this.nodeObjList[index]) {
    this.nodeObjList[index].arr = this.nodeObjList[index].arr.filter(item => item.id != id)
    this.nodeObjList[index].str = this.nodeObjList[index].arr.map(item => item.name).join(',')
  }
},
```

### 6. methods：改造提交时的校验与组装

```js
// 校验：遍历每个需要选择审批人的节点，人员不能为空
let allValid = true
this.processNodeList.forEach((node, idx) => {
  if (this.hasSprScope(node) && this.nodeObjList[idx] && this.nodeObjList[idx].arr.length === 0) {
    this.$message.warning(`请选择「${node.nodeName}」的${this.isCcNode(node) ? '抄送' : '审批'}人`)
    allValid = false
  }
})
if (!allValid) return

// 组装 customProcessConfigurationDTOList：将接口返回的节点数据深拷贝后放入
// 对于 isselfSelect===1 或 sprScope===4 的节点，将选中的审批人数据写到节点外层
const customProcessConfigurationDTOList = this.processNodeList.map((node, idx) => {
  const nodeCopy = JSON.parse(JSON.stringify(node))
  if (this.hasSprScope(node) && this.nodeObjList[idx]) {
    const selectedPersons = this.nodeObjList[idx].arr
    if (selectedPersons && selectedPersons.length > 0) {
      nodeCopy.chooseObjects = selectedPersons.map(p => p.id).join(',')
      nodeCopy.chooseObjectsName = selectedPersons.map(p => p.name).join(',')
      nodeCopy.sprScopeName = node.nodeName || ''
    }
  }
  return nodeCopy
})
this.model['customProcessConfigurationDTOList'] = customProcessConfigurationDTOList
```

groupedLog() {

## 节点数据结构

后端返回的节点数组关键字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | 节点ID |
| `nodeName` | String | 节点名称（页面显示） |
| `nodeProperties` | Number | 节点性质：`1`=审批节点，`2`=抄送节点 |
| `px` | Number | 排序（越小越靠前） |
| `isselfSelect` | Number | 是否自选：`1` 时显示「添加审批人」按钮 |
| `sprScope` | Number | 审批范围：`4` 时显示「添加审批人」按钮 |
| `sprScopeName` | String | 审批范围名称（提交时回传） |
| `kjSprType_dictText` | String | 空级审批类型文本（如"直属经理"，users 为 null 时显示） |
| `users` | Array/null | 预设用户 `[{ chooseObjects, chooseObjectsName, sprScopeName }]`，为 null 时展示 kjSprType_dictText |
| `roles` | Array | 预设角色 `[{ chooseObjects, chooseObjectsName }]` |
| `departments` | Array | 预设部门 `[{ chooseObjects, chooseObjectsName }]` |

---

## 关键交互规则

1. **添加按钮显示条件：** 节点 `isselfSelect === 1` 或 `sprScope === 4` 时显示「添加审批人/抄送人」按钮；空级审批节点（`kjSprType` 有值，即直属主管/直属经理/直属总监）显示「自选审批人」按钮。
2. **节点类型区分：** `nodeProperties === 2` 为抄送节点（按钮文案显示「添加抄送人」），否则为审批节点（「添加审批人」）。
3. **默认人员：** 从 `users`、`roles`、`departments` 三个数组中提取并合并去重，作为初始已选人员。
4. **空级审批展示：** `kjSprType` 有值的节点（直属主管/直属经理/直属总监），后端解析出的人员在节点外层 `chooseObjects`/`chooseObjectsName`（可为多人逗号分隔），需解析成与普通节点一致的头像 tag；tag 可删除，节点上同时显示「自选审批人」按钮（即交互与用户审批节点完全一致，不受 `isselfSelect`/`sprScope` 控制）。仅当节点不可编辑且无人员 tag 时，才回退展示静态文本。
5. **选择人员追加逻辑：** 新选择的人员采用追加合并（按 id 去重），不会覆盖接口返回的默认人员。
6. **排序：** 按 `px` 字段升序排列。
7. **详情模式：** 不调用节点接口，继续使用原有的 `ApprovalTimeline` 时间轴组件。
8. **提交数据结构：** 将整个节点配置放入 `customProcessConfigurationDTOList`，对于可编辑审批人的节点（`isselfSelect===1` 或 `sprScope===4`，或 `kjSprType` 有值的空级审批节点），在节点外层写入 `chooseObjects`、`chooseObjectsName`、`sprScopeName` 三个字段；空级审批节点即使接口已带出默认人员，也要按删除/自选后的最终结果回写。提交前校验同样覆盖这些节点，人员为空时提示「请选择「节点名」的审批人」。
9. **节点较多时滚动：** 审批流程区域需加最大高度与滚动条，避免节点过多撑破弹窗。
10. **详情数据字段变化：** 后端返回的详情审批记录从 `approvalRecordList` 改为 `customProcessSqdSpjdList`，字段名 `spFlow` → `nodeName`、`name` → `sprName`，`ApprovalTimeline` 组件和列表页都要同步改造。
11. **已移除功能：** 前端"是否多人审批（dx）"开关被移除，改为由后端节点配置控制；编辑模式下审批人回填逻辑也移除，改为重新拉取动态节点配置。
