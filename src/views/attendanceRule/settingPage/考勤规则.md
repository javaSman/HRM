## 核心数据结构矛盾 & 解决方案

整个模块最大的复杂度来源是：**后端存储的数据结构和前端 UI 展示/交互需要的数据结构不一致**。理解这些"翻译层"是理解代码的关键。

---

### 矛盾一：后端数组 vs 表格列

**后端返回的数据**（固定打卡模式下）：
```js
record = {
  dkfs: 0,
  hrKqRuleGddatedk: [
    { sjd: 'morning',     sbdaate: '08:00', xbdate: '12:00' },
    { sjd: 'afternoon',   sbdaate: '13:00', xbdate: '18:00' },
    { sjd: 'nightTop',    sbdaate: '18:00', xbdate: '00:00' },
    // ... 可能还有更多段
  ]
}
```

**表格需要的结构**（列定义用了 `dataIndex: 'morning.sbdaate'`）：
```js
row = {
  dkfs: 0,
  morning:   { sbdaate: '08:00', xbdate: '12:00' },  // → 上午时段列读取
  afternoon: { sbdaate: '13:00', xbdate: '18:00' },  // → 下午时段列读取
  nightTop:  { sbdaate: '18:00', xbdate: '00:00' },  // → 上半夜班列读取
  nightBottom: { ... },                                // → 下半夜班列读取
}
```

**为什么表格列要这样定义？** 因为 ant-design-vue 的表头是固定的四个时段分组（上午/下午/上半夜/下半夜），每个分组下两个子列（开始/结束）。只有把时段数据提升为行的顶层属性，列的 `dataIndex` 才能直接点号取值。如果用 slot 模板从数组里 find 取，每个单元格都要遍历数组，写法繁琐且性能差。

**翻译层 → `dataSource` watcher**（[HrKqRuleList.vue:383-407](HrKqRuleList.vue#L383-L407)）：

```js
// 监听 JeecgListMixin 注入的 dataSource（后端返回的原始数据）
// 将 hrKqRuleGddatedk 数组 → 行的顶层属性，供表格列直接 dataIndex 取值
dataSource: {
  handler(newVal) {
    let arr = JSON.parse(JSON.stringify(newVal))  // 深拷贝，避免污染原始数据

    arr.forEach(item => {
      if (item.dkfs == 0) {                        // 只处理固定打卡
        item.hrKqRuleGddatedk.forEach(period => {
          // 用 period.sjd（时段类型，如 'morning'）作为属性名
          // 把 {sbdaate, xbdate} 挂到行对象上
          item[period.sjd || 'morning'] = {
            sbdaate: period.sbdaate,
            xbdate: period.xbdate
          }
        })
      }
    })

    this.dataSourceNew = arr  // 表格绑定的是 dataSourceNew，不是原始 dataSource
  },
  deep: true
}
```

**数据流**：
```
后端 API → JeecgListMixin.dataSource → watcher 转换 → dataSourceNew → a-table 渲染
```

表格中非固定打卡（自由打卡/总时长打卡）的规则，`dkfs != 0`，watcher 不做转换，四个时段列渲染时 `dataIndex` 取到 `undefined`，customRender 返回 `-`。

### 矛盾二：加班/旷工字段归属

**后端存储**：加班/旷工字段（`absenteeHour`、`startoutTime`、`minoutTime`、`multiple`、`check`）写在 `hrKqRuleGddatedk` 数组的**每个元素**里：

```js
hrKqRuleGddatedk: [
  { sjd: 'morning', sbdaate: '08:00', ..., absenteeHour: 1, startoutTime: '18:30', ... },
  { sjd: 'afternoon', sbdaate: '13:00', ..., absenteeHour: 1, startoutTime: '18:30', ... },
]
```

**前端 UI**：旷工和加班是**规则级别**的配置，只需填一次，不属于任何时段。表单里它们放在独立的"旷工时间配置"和"加班时间配置"区域（黄色高亮），与时间段列表平级。

**翻译层 → 两处映射**：

| 方向 | 位置 | 做什么 |
|---|---|---|
| 后端→前端（编辑回显） | `edit()` | 从 `record.hrKqRuleGddatedk[0]` 取出加班/旷工字段 → 写入 `model.absenteeHour` 等顶层字段 |
| 前端→后端（提交） | `getSubmitPayload()` | 将 `model.absenteeHour` 等顶层字段 → 写入 `sjd` 数组的每个元素 |

**为什么不做成 `model.hrKqRuleGddatedk.sjd[0].absenteeHour` 直接绑定？** 因为 `sjd` 是用户可以随意增删的动态数组——用户删掉第一个时间段，加班配置就跟着消失了，还需要额外写保护逻辑。保持顶层字段独立，语义清晰且健壮。

## CHECKIN_TYPE_OPTIONS —— 打卡方式路由表

```js
{ label: '固定时间打卡', value: '0', ObjectKey: 'hrKqRuleGddatedk' },
{ label: '自由打卡',     value: '1', ObjectKey: 'hrKqRuleZydatedk' },
{ label: '免打卡',       value: '3', ObjectKey: 'hrKqRuleGddatedk' },  // 复用固定打卡结构
{ label: '总时长打卡',   value: '2', ObjectKey: 'hrKqRuleZscdk' },
```

`ObjectKey` 决定了 UI 渲染哪个配置区块、提交时附带哪个子对象、编辑时解析哪个字段。固定打卡和免打卡共用 `hrKqRuleGddatedk`，区别仅是免打卡不显示上下班时间编辑。

## 关键函数说明

| 函数 | 位置 | 作用 |
|---|---|---|
| `createDefaultModel()` | HrKqRuleForm.vue | 生成纯净默认 model，新增和编辑合并的基准 |
| `normalizeRuleConfigModel(model)` | HrKqRuleForm.vue | 防御性补齐：深拷贝默认值，保证三个子配置对象不为空，`sjd` 至少有一条 |
| `edit(record)` | HrKqRuleForm.vue | **后端→前端转换**：数组→sjd、逗号串→数组、JSON→scopeSelection、sjd[0]→加班/旷工字段回显 |
| `getSubmitPayload()` | HrKqRuleForm.vue | **前端→后端转换**：数组→逗号串、scopeSelection→JSON、sjd展开+加班/旷工字段注入 |
| `dataSource` watcher | HrKqRuleList.vue | **数组→平铺**：将 `hrKqRuleGddatedk` 数组按 `sjd` 值展开为行的顶层属性，供表格列 `dataIndex` 取值 |
| `handleCheckinTypeChange()` | HrKqRuleForm.vue | 切换打卡方式时重置三个子配置对象为默认值 |
