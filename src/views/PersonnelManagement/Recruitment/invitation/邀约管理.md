# 简历管理模块说明（技术交接文档）

> 本文档以当前代码实际实现为准，描述简历管理页面的结构、字段、状态流转与接口。
> 技术栈：Vue 2.6 + ant-design-vue 1.7 + JEECG Boot 前端框架（`JeecgListMixin`）。

---

## 1. 模块定位与整体结构

简历管理采用「**招聘计划维度**」的两层结构，而不是直接铺开全部候选人：

```
简历管理首页（计划看板）
  └─ 点某行「详情」  → 岗位详情盒（ResumeDetailBox）
                         ├─ 左：该岗位的招聘计划信息
                         └─ 右：该岗位下的候选人简历表（ResumeInterviewTable）
  └─ 点某行「简历数量」→ 简历右抽屉（ResumeListDrawer，卡片式预览）
```

- 首页一行 = 一条招聘计划（岗位）数据，聚合展示该岗位下各状态简历数量。
- 候选人的邀约、确认面试、淘汰、暂停等操作都收敛在「岗位详情盒」右侧的简历表内完成。

## 3. 页面流转与交互

### 3.1 首页 `index.vue`（计划看板）

- **统计卡（数量统计）**：`全部` / `进行中` / `已完成`，点击卡片按计划状态 `dqzt` 筛选；数量来自 `/zpManage/hrmJlgl/getTotal`。
- **查询区**：公司（下拉）、部门（级联，依赖公司）、岗位名称（`postName`）。
- **操作按钮**：查询、重置、导出、导入（Excel）、批量操作（仅勾选后出现，当前只提供「删除」）。
- **表格列**：见 [5.1](#51-首页计划看板字段)。
- 行操作：
  - 点「**详情**」→ 打开岗位详情盒 `ResumeDetailBox`。
  - 点「**简历数量**」数字 → 打开右侧抽屉 `ResumeListDrawer`。

### 3.2 岗位详情盒 `ResumeDetailBox.vue`

- **顶部栏**：岗位名称（`postName`）+ 计划状态标签（`dqzt`，已完成绿色 / 否则蓝色）；右侧按钮：
  - `简历收集完毕`：二次确认后调用 `/zpManage/hrmJlgl/complete`。
  - `返回列表`：回到首页看板。
- **6 张统计卡**（数量来自带入的计划记录聚合字段）：简历数量、待邀约数量、已邀约数量、已确认面试数量、不通过数量、暂停邀约数量。
- **左侧「岗位信息」**：按 `record.zpjhid` 调用 `/zpManage/hrmZpjh/list` 取招聘计划后展示，字段见 [5.2](#52-岗位信息字段-resumedetailbox-左侧)。
- **右侧「简历」**：`ResumeInterviewTable`，标题展示 `简历（共 jlsl 份）`。

### 3.3 候选人简历表 `ResumeInterviewTable.vue`

- **状态 Tabs**：全部 / 待邀约 / 已邀约 / 已确认面试 / 不通过 / 暂停邀约；切换按候选人状态 `dqzt` 过滤。
- **搜索**：姓名（`xm`）、学历（`xl`）。
- **右上角**：新增简历（`HrmJlglModal`，自动带入当前岗位上下文）、导出。
- **批量操作栏**：已选择 N 项 / 清空，并按当前 Tab 显示对应批量按钮（**不支持跨状态批量操作**）：

| 当前 Tab | 可用批量操作 |
| --- | --- |
| 待邀约 / 暂停邀约 | 批量邀约、批量淘汰 |
| 待邀约 | 批量暂停邀约 |
| 已邀约 | 批量确认面试、批量淘汰 |
| 不通过 | 批量删除 |
| 已确认面试 | 无批量按钮 |

- **行操作**：`编辑`（**仅待邀约**状态显示）、`详情`。
- 表格列见 [5.3](#53-候选人简历表字段)。

### 3.4 简历右抽屉 `ResumeListDrawer.vue`

- 由首页「简历数量」打开，宽度 800，卡片式展示该岗位下候选人。
- Tabs 数量取自计划行的聚合字段（`jlsl/dyy/yyy/yqrms/ytt/ztyy`），切换 Tab 按 `dqzt` 过滤。
- 卡片展示头像（男蓝 / 女粉渐变）、姓名、性别、年龄、学历、专业、期望薪资、状态标签，并提供「简历预览」（打开 PDF）。
- 底部为分页器。

### 3.5 候选人「详情 / 批量邀约 / 批量淘汰」弹窗 `ResumeProcessModal.vue`

一个弹窗承载三种模式（`mode`）：

| mode | 标题 | 宽度 | 布局 |
| --- | --- | --- | --- |
| `detail` | 详情 | 800（不通过详情 1200） | 中：个人信息 + 右：邀约/淘汰只读 |
| `batchInvite` | 批量邀约 | 1300 | 左：人员列表 + 中：个人信息 + 右：邀约表单 |
| `batchEliminate` | 批量淘汰 | 1300 | 左：人员列表 + 中：个人信息 + 右：淘汰表单 |

- 批量模式下，左侧候选人列表点击只切换中间「个人信息」，**右侧表单内容不重置**（同一份内容统一应用于全部候选人）。
- 邀约 / 淘汰表单字段见 [5.4](#54-邀约--淘汰字段-resumeprocessmodal)。

## 4. 状态流转

### 4.1 招聘计划状态（首页，字段 `dqzt`）

```
进行中  ──(简历收集完毕 complete)──►  已完成
```

### 4.2 候选人状态（简历表，字段 `dqzt`）

```
                 ┌──(批量邀约 invite)──► [待确认 / 已邀约] ──(确认面试 confirmInterview)──► 已确认面试
  待邀约 ────────┼──(暂停邀约 pauseInvite)──► 暂停邀约 ──(批量邀约 invite)──► [待确认 / 已邀约]
                 └──(批量淘汰 eliminate)──► 不通过 ──(删除 deleteBatch)──► 物理删除

  [待确认 / 已邀约] ──(批量淘汰 eliminate)──► 不通过
```

> ⚠ **状态取值存在前后端不一致风险（需确认）**：`ResumeProcessModal.buildPayload` 中邀约提交对象里 `dqzt` 被写了两次（先 `'已邀约'`，后 `'待确认'`）。JS 对象后一个键生效，实际提交的是 **`待确认`**；但状态 Tabs、颜色映射使用的是 **`已邀约`**。此处需与后端确认邀约成功后候选人状态究竟应为哪个，并统一代码（见第 8 节 TODO）。

补充规则：

- 只有 `待邀约` 状态的候选人允许「编辑」。
- 邀约人 `yyr`、邀约时间 `yysj`、淘汰操作人 `ttczr`、淘汰时间 `ttsj` 默认由前端在提交时带入：操作人 = 当前登录人 `perInfo.name`，时间 = 当前时间（`getNowText`，精确到分）。

### 6.3 批量提交载荷格式

`ResumeProcessModal` 的邀约 / 淘汰均为「每个候选人一条」的**数组**，将统一填写的内容覆盖到每个勾选 id：

```js
// 批量邀约（数组，每人一条）
[
  {
    id,                       // 候选人 id
    msr, msxs, mssj, zwqrsj, msdd, xyxdcl, remark,
    yyr: '当前登录人姓名',
    yysj: '当前时间',
    dqzt: '待确认'             // ⚠ 重复键问题，实际生效值，见 4.2
  },
  ...
]

// 批量淘汰（数组，每人一条）
[
  { id, ttyy, ttczr: '当前登录人姓名', ttsj: '当前时间', dqzt: '不通过' },
  ...
]
```

批量确认面试 / 暂停邀约（`ResumeInterviewTable.batchUp`）则直接对 `selectionRows` 深拷贝后逐条改写 `dqzt`（`已确认面试` / `暂停邀约`）整体提交。

## 8. 待办 / 风险项（如实标注）

1. **邀约后状态取值不一致（需后端确认）**：邀约提交载荷中 `dqzt` 重复定义，实际提交 `待确认`，而 Tabs / 颜色映射用 `已邀约`。需确认正确状态值并统一。
2. **`ResumeInviteForm.vue` 为孤儿文件**：全工程无引用，确认无用后可删除。
3. **`ResumeInterviewTable.handleTabChange` 已实现按状态过滤**，但方法内仍保留旧的 `TODO: tabs 暂不过滤` 注释，注释与实现不符，可清理。
4. **`ResumeInterviewTable` 中的 watch**：监听 `dataSource` 后延时 800ms 向父组件 `$emit('ok')`，属于时序妥协写法，后续如出现刷新抖动建议改为显式事件触发。
5. **简历表「导入」按钮当前被注释**（工具栏仅保留新增、导出），如需启用需放开模板并确认导入接口。
6. 本模块**已不再使用**字段配置（`columnConfigMixin` / `resumeColumnsMixin`）及旧版的「待分配、招聘类型、邀约人列」等设计；如在其他文档中看到相关描述均属历史内容，以本文档为准。
