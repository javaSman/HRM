门禁人员接口调试台 PUSH 默认 · A4 兼容

调试 /attendance/hrmGuardMember 增删改查；默认通过熵基 PUSH 队列由设备轮询下发，配置为 A4 时才由平台直连设备。仅用于联调，正式页面后续按业务实现。

① 连接配置

推荐：把本文件放在前端 public/ 下，npm run dev 后访问 http://localhost:3000/access-control-debug.html，用「同源代理 /qr-hrm」走 dev 代理，免 CORS、复用登录态。直连后端需后端开启 CORS。

Token 获取：在已登录的系统页面打开浏览器 DevTools → Application → Local Storage → 找 pro__Access-Token 的 value；或任意接口请求头里的 X-Access-Token。

② 门禁设备检查（下发前提）

只有 hr_kq_device 中 sbyt='门禁' 且 macAddress 填了设备 URL 的记录才会被下发。没有则增删改时日志打 未找到门禁闸机设备，跳过下发，不会真正连接闸机。

没有设备？用 SQL 插一条测试设备 
INSERT INTO hr_kq_device (id, sbmc, sbyt, mac_address, create_time)
VALUES ('test-gate-1', '测试闸机1', '门禁', 'http://192.168.1.135:8091', now());

④ 新增 / 编辑门禁人员

提交后会保存并异步下发到所有门禁闸机。no（工号）必填，作为下发的 employee_number；photo 填可访问的图片 URL（服务端会下载转 base64 落库 + 下发人脸）。

⑤ 单条查询 / 删除

删除会异步从所有门禁闸机清除该工号白名单，并把本地人脸置 status=1。
